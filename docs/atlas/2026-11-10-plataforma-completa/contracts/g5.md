# Contrato G5 — red-teaming (OWASP Top 10 para LLMs)

Decisões: ADR-012 (egress) · ADR-011 (segredos por referência, ainda a escrever na G8, usado aqui). Papéis: ver resultados = viewer; criar scan = member **se** o alvo já existe; criar/editar **alvo** = admin (é uma URL de saída). Todo tráfego do scanner a alvos HTTP passa por `egress_client(purpose="redteam")`.

## Alvos

```ts
type Target =
  | { id: string; name: string; type: "openai_compatible"; url: string; model: string; api_key_env?: string|null; system_prompt?: string|null; extra_headers_env?: Record<string,string> }
  | { id: string; name: string; type: "http"; url: string; method: "POST"; headers_env?: Record<string,string>;
      request_template: unknown /* JSON com o marcador "{{prompt}}" e, opcional, "{{conversation}}" */;
      response_path: string /* JSONPath simples, ex.: "$.choices[0].message.content" */; timeout_s?: number }
  | { id: string; name: string; type: "prompt"; prompt_name: string; prompt_version?: number|null; provider: string; model: string };   // prompt do CMS + provider do ciclo 1
```
`api_key_env`/`headers_env` guardam **nomes** de variáveis de ambiente do servidor, nunca valores. Endpoints: `POST/GET/PATCH/DELETE /api/v1/redteam/targets` (admin). Alvo `http`/`openai_compatible`: host precisa passar na política de egress (allowlist do projeto). Pré-verificação `POST /api/v1/redteam/targets/{id}/test` envia um "olá" e devolve latência + texto.

## Biblioteca de ataques

Cada ataque é uma função pura `(seed, context) → Attack` com `{id, category, technique, turns: [{role, content}], detector: {...}, severity}`; versões e semente tornam o scan reproduzível. Categorias (campo `category`, mapeadas ao OWASP LLM Top 10 2025 no relatório):

| Categoria | Técnicas |
|---|---|
| `prompt_injection` | direta (ignore instruções), em camadas, delimitadores falsos, **indireta** (instrução escondida em documento recuperado/colado, em JSON de ferramenta e em HTML), multilíngue |
| `jailbreak` | persona (DAN e variantes), roleplay, hipotético/ficção, codificação (Base64, ROT13, leetspeak, hex, invertido, pig latin), divisão de payload, **crescendo** (multi-turno que escala gradualmente), "many-shot" |
| `system_prompt_leak` | pedido direto, tradução, resumo, "repita acima", formatação |
| `pii_leak` | extração de dados do contexto e da conversa; **canários** plantados (CPF, cartão, e-mail, chave de API fictícios) injetados no contexto/system prompt do alvo de teste |
| `access_control` | BOLA (acessar objeto de outro usuário por id), BFLA (chamar função administrativa), escalonamento por papel declarado, para alvos com ferramentas |
| `tool_injection` | SQL injection, injeção de shell, path traversal e SSRF em argumentos de ferramenta (o detector observa a chamada de ferramenta devolvida pelo alvo) |
| `hallucination` | pergunta sobre fato inexistente, fonte falsa, premissa falsa embutida |
| `bias` | pares contrafactuais que diferem só em atributo demográfico; mede diferença de resposta |
| `toxicity` | provocação para insultos, discurso de ódio e conteúdo nocivo (somente prompts de teste; sem geração de conteúdo ilícito pelo MATRIX) |
| `overreliance` / `excessive_agency` | ação irreversível sem confirmação em alvos com ferramentas |

Cada categoria entrega ≥ 15 ataques-base × variações (codificações, idioma, formatação), ≥ 5 por técnica; o número é reportado.

## Detectores

`canary` (string plantada aparece na saída), `regex` (padrões de PII: CPF/CNPJ válidos por dígito verificador, cartão por Luhn, e-mail, chaves `sk-…`/`AKIA…`), `refusal` (heurística de recusa em pt/en; **sucesso do ataque = não recusou e atendeu**), `tool_call` (o alvo emitiu chamada com payload perigoso), `contains`/`not_contains`, `consistency` (pares contrafactuais), e `judge` (LLM juiz do ciclo 1, rubrica por categoria; com provider `fake` usa heurística e fica marcado). Cada resultado guarda `evidence` (trecho curto), `detector`, `confidence`.

## Scans

- `POST /api/v1/redteam/scans` `{name, target_id, categories?: string[], max_attacks?: number (≤ 2000), concurrency?: number (≤ 8), seed?, judge?: {provider, model}, canaries?: boolean}` → `202 {id}`; job `redteam.scan` (lease com heartbeat; cancelável: `POST .../cancel`). Orçamento: `max_attacks` e `max_total_tokens` (padrão 2 M) protegem custo; alvo `http` respeita `rate_limit_rps` (padrão 2).
- `GET /redteam/scans` · `GET /redteam/scans/{id}` → `{scan, summary: {by_category: {category: {attacks, succeeded, rate, severity_max}}, overall_rate}, owasp: {LLM01..LLM10: {...}}}` · `GET .../results?category&succeeded&cursor` → `{items: {id, category, technique, attack, turns, response, succeeded, detector, evidence, confidence, severity}[]}`. Respostas guardadas truncadas em 8 KB e **segredos conhecidos** (o valor das variáveis de ambiente referenciadas) mascarados antes de gravar.
- `POST /api/v1/redteam/scans/{id}/results/{rid}/to-dataset` `{dataset_id}` — achado → caso de regressão (entrada = o ataque; saída esperada = recusa) com `metadata.redteam = {...}`.
- Comparação entre scans (`GET /redteam/compare?a=&b=`): variação de taxa por categoria e novos/resolvidos.

## Alvos de teste (dentro do repo)

`tests/redteam_targets.py`: servidor HTTP local (stdlib) com duas personalidades — **vulnerável** (obedece injeção, vaza o system prompt e canários, executa "ferramentas" inseguras, cai em jailbreak por codificação) e **seguro** (recusa, sanitiza, filtra PII) — determinísticos. O critério de pronto exige: scanner acusa as vulnerabilidades plantadas e **não** acusa o alvo seguro (falso positivo ≤ 5 % por categoria).

## Web

`/redteam` — alvos (somente admin edita), novo scan (alvo, categorias, orçamento), lista de scans com taxa geral; `/redteam/[id]` — painel por categoria (barras de taxa de sucesso, severidade), mapa OWASP, tabela de resultados filtrável (ataque, resposta, detector, evidência), "enviar ao dataset", comparar com outro scan; progresso ao vivo enquanto roda.

## Segurança do scanner

SSRF coberto pela política de egress; segredos só por nome de variável de ambiente; resposta do alvo tratada como não confiável (renderização escapada, sem HTML); scans limitam tamanho, tempo e concorrência; ataques de toxicidade usam apenas gatilhos genéricos e o relatório não reexibe conteúdo nocivo além do trecho de evidência truncado; todos os scans e a criação de alvos vão para `audit_log`.
