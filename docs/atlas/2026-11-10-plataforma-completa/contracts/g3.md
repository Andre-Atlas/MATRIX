# Contrato G3 — registry de modelos/LoRA, versionamento de datasets, linhagem

Depende de G0 (artifact store, RBAC, egress) e G1 (runs). Decisões: ADR-007 (artifacts; LakeFS/DVC como adaptadores). Leitura = viewer; criar versões/aliases de staging = member; produção, rebaixar, arquivar, webhooks = admin.

## 1. Model & LoRA Registry

```ts
type ModelFlavor = "sklearn"|"xgboost"|"lightgbm"|"pytorch"|"onnx"|"safetensors"|"transformers"|"lora"|"custom";
type RegisteredModel = { id: string; name: string; description: string|null; tags: string[]; created_at: string;
  latest_version: number|null; aliases: Record<string, number>; stages: Record<"staging"|"production", number|null> };
type ModelVersion = { id: string; model: string; version: number; flavor: ModelFlavor; stage: "none"|"staging"|"production"|"archived";
  aliases: string[]; run_id: string|null; dataset_version_id: string|null;
  artifacts: {artifact_id: string; path: string; size: number; sha256: string}[];    // arquivos do modelo (pesos, config, tokenizer…)
  base_model: {name: string; version?: number|null; ref?: string|null}|null;          // obrigatório para flavor "lora"
  lora: {rank: number; alpha: number; target_modules: string[]; dropout?: number}|null;
  signature: {inputs: {name: string; dtype: string; shape?: (number|null)[]}[]; outputs: {...}[]}|null;
  metrics: Record<string, number>; params: Record<string, unknown>; notes: string|null; tags: string[];
  created_at: string; created_by: string|null };
```

- `POST /models` `{name, description?, tags?}` (nome `^[A-Za-z0-9][A-Za-z0-9._/-]{0,199}$`, único por projeto) → `201`. `GET /models` · `GET /models/{name:path}` → `{model, versions}` · `DELETE /models/{name}` (admin; recusa se alguma versão em produção).
- `POST /models/{name}/versions` `{flavor, artifact_ids: [..], run_id?, dataset_version_id?, base_model?, lora?, signature?, metrics?, params?, notes?, tags?}` → `201 ModelVersion` (versões imutáveis e numeradas; os artefatos precisam existir e pertencer ao projeto; `run_id` precisa pertencer ao projeto; `lora` exige `base_model` e vice-versa; sem `metrics` copia o `summary` do run). Member. `flavor` `safetensors`/`lora` valida que algum artefato termina em `.safetensors` ou `.bin`/`.gguf` (aceita também `adapter_config.json`).
- `GET /models/{name}/versions/{version|@alias}` → `ModelVersion` · `PATCH .../versions/{v}` `{notes?, tags?}` (nada além disso muda).
- **Aliases** (`@champion`, `@challenger`, livres `^[a-z][a-z0-9_-]{0,49}$`): `PUT /models/{name}/aliases/{alias}` `{version}` (move; `champion` exige admin) · `DELETE`.
- **Estágios**: `POST /models/{name}/versions/{v}/stage` `{stage, comment?}` — `staging` member; `production`/`archived` admin. Uma versão em `production` por modelo (a anterior vai para `archived` na mesma transação, registrando no histórico). Registro em `model_stage_history(model, version, from, to, actor, comment, ts)`; `GET .../history`.
- **Webhooks de CI/CD**: `POST/GET/DELETE /models/{name}/webhooks` (admin) `{url, events: ["version.created","stage.changed","alias.moved"], secret?}`; o `secret` é gerado pelo servidor quando omitido e mostrado uma única vez. Entrega assíncrona (job `webhooks.deliver`) com **assinatura** `X-Matrix-Signature: sha256=<hmac(secret, timestamp + "." + corpo)>` + `X-Matrix-Timestamp`, `X-Matrix-Event`, `X-Matrix-Delivery`; retries com backoff (5 tentativas); toda requisição passa **obrigatoriamente** por `egress_client` (ADR-012). `GET .../webhooks/{id}/deliveries` (status, tentativas, último código; sem corpo da resposta). Segredos guardados cifrados em repouso com `MATRIX_SECRET_KEY` (Fernet); nunca devolvidos depois da criação.
- **Download**: `GET /models/{name}/versions/{v}/files` → `{files: [{path, size, sha256, url}]}` (URLs pré-assinadas ou do próprio servidor) para o SDK baixar o modelo.

SDK: `run.log_model(name, path_or_obj, flavor, ...)` (envia arquivos como artefatos, cria a versão ligada ao run e ao dataset do run), `matrix_sdk.registry.get_model(name, alias="champion")` e `.download(dir)`, `register_lora(name, adapter_dir, base_model, ...)`.

## 2. Versionamento de datasets

Complementa os golden datasets do ciclo 1 (itens de avaliação) com **datasets de arquivos** para treino e com **snapshots** dos golden.

```ts
type DatasetKind = "files"|"golden";
type DataVersion = { id: string; dataset: string; version: number; parent_version: number|null;
  manifest_sha256: string; file_count: number; total_bytes: number; message: string|null;
  source: { type: "upload"|"snapshot"|"lakefs"|"dvc"; ref?: string|null }; created_at: string; created_by: string|null };
type ManifestEntry = { path: string; sha256: string; size: number; artifact_id: string|null; media_type?: string };
```

- `POST /data-sets` `{name, kind, description?}` (`/api/v1/data-sets`, para não colidir com `/datasets` do ciclo 1) · `GET /data-sets` · `GET /data-sets/{name}`.
- `POST /data-sets/{name}/versions` `{message?, parent_version?, files: ManifestEntry[]}` — cada arquivo referencia um artefato já enviado (deduplicado pelo store) → `201 DataVersion`; `manifest_sha256` = hash do manifesto canônico (JSON ordenado por caminho); idempotente: manifesto idêntico ao da última versão devolve a mesma versão (`200`). Caminhos normalizados (sem `..`, sem `/` inicial, ≤ 1024). Limites: 100 000 arquivos por versão.
- `GET /data-sets/{name}/versions/{v}` → `{version, files (paginados)}` · `GET .../versions/{a}/diff/{b}` → `{added: [], removed: [], modified: [{path, from, to}], unchanged_count}`.
- `POST /data-sets/{name}/snapshot` `{dataset_id}` — congela um golden dataset do ciclo 1 como versão `kind=golden` (itens serializados em JSONL como artefato + manifesto). Experimentos ganham `dataset_snapshot_version` opcional (`POST /experiments {dataset_version: ...}`) e passam a usar esse snapshot em vez dos itens vivos (reprodutibilidade).
- **Adaptadores externos** (`source.type` `lakefs`/`dvc`), somente leitura: `POST /data-sets/{name}/link` `{type: "lakefs", repo, ref, path?}` registra um ponteiro e importa o manifesto via API do LakeFS (listagem de objetos com checksum) **usando `egress_client`** e uma credencial referenciada por nome de variável de ambiente (nunca guardada); `{type: "dvc", repo_url?, dvc_file_content}` interpreta um arquivo `.dvc`/`dvc.lock` enviado (md5 + path + size) sem acessar remoto. Os blobs não são copiados; a versão marca `artifact_id: null` e `ref`.

SDK: `run.use_dataset(name, version=None)` (liga o run à versão e a registra em `runs.dataset_version_id`), `matrix_sdk.data.push(name, directory, message=None)` (hash local, envia só o que falta, cria a versão), `matrix_sdk.data.pull(name, version, dir)`.

## 3. Linhagem

Grafo derivado (sem tabela própria de arestas além de `lineage_edges` materializada na escrita para consultas rápidas): nós `data_version`, `run`, `model_version`, `experiment`, `benchmark` (G7), `sweep`; arestas `consumed_by` (data_version → run), `produced` (run → model_version), `base_of` (model_version → model_version/lora), `evaluated_by` (model_version → experiment/benchmark), `member_of` (run → sweep).

- `GET /lineage?node=<kind>:<id>&direction=up|down|both&depth=3` → `{nodes: {id, kind, label, status?, meta}[], edges: {from, to, kind}[]}` (≤ 500 nós; truncado sinalizado em `truncated`).
- As arestas são gravadas quando: um run é criado com `dataset_version_id`; uma versão de modelo é registrada (run → modelo, base → lora); um experimento/benchmark é criado apontando para uma versão de modelo ou de dataset.

## Web

`/models` (lista, estágios, aliases), `/models/[name]` (versões, comparação lado a lado de métricas/params entre versões, promoção com confirmação e comentário, aliases, webhooks e entregas, arquivos), `/data-sets` e `/data-sets/[name]` (versões, diff entre versões com contagem e lista, arquivos, origem), e **grafo de linhagem** em React Flow (nó selecionado em qualquer página abre `/lineage` focado nele; filtros por tipo; direção).
