# Contrato G4 — Vector Space & Drift Observatory

Decisões: ADR-009. Leitura = viewer; criar job/monitor = member; apagar monitor = admin. Cálculo no worker (extra `analytics`).

## 1. Embeddings

ClickHouse `embeddings(project_id, collection, ref, kind, model, dim, vector Array(Float32), text_preview, ts, version)` `ReplacingMergeTree(version)` por `(project_id, collection, ref)`; `kind` ∈ `query|document|output|image|other`; `ref` identifica a origem (`trace:<id>:<span>`, `doc:<id>`, ou livre). Limites: `dim` ≤ 4096, ≤ 1000 vetores por requisição, 50 M vetores por projeto (configurável).

- `POST /api/v1/embeddings` `{collection, model, items: [{ref, kind, vector, text?, metadata?}]}` → `202 {accepted, rejected}` (member). Vetores NaN/Inf rejeitados; `dim` consistente por (coleção, modelo).
- `GET /api/v1/embeddings/collections` → `{items: {collection, kind_counts, model, dim, count, updated_at}[]}`.
- **Captura automática**: a ingestão OTLP (ciclo 1) hoje descarta `embedding.embeddings.*.embedding.vector`; passa a **desviar** esses vetores para `embeddings` (coleção `traces`, `kind` = `query` para spans EMBEDDING cujo pai é RETRIEVER/CHAIN de pergunta, `document` para chunks), mantendo a remoção do vetor dos atributos do span.
- **Job `embeddings.backfill`** `{collection, source: "trace_inputs"|"retrieved_documents"|"dataset_items", dataset_id?, since?, provider: {name, model}}`: embeda textos que ainda não têm vetor. Provider `openai` (via `MATRIX_OPENAI_BASE_URL`), `hash` (offline, determinístico) — o `hash` serve para testes e demonstração e é rotulado como tal na UI.

## 2. Projeção, clusters e lacunas

Job `vectors.project` `{collections: [{collection, kinds?, weight?}], method: "umap"|"pca", dims: 2|3, n_neighbors?, min_dist?, min_cluster_size?, sample?: number, seed?, metric_scores?: "faithfulness"|...}` → `202 {job_id, projection_id}`.

```ts
type Projection = { id: string; status: "queued"|"running"|"done"|"failed"; created_at: string; params: {...}; error: string|null;
  points: number; clusters: Cluster[]; gaps: Gap[] };
type Cluster = { id: number; size: number; centroid_2d: number[]; kind_counts: Record<string, number>; label: string|null;
  top_terms: string[]; mean_scores: Record<string, number>; error_rate: number|null };
type Gap = { cluster_id: number; query_count: number; nearest_document_distance: number; examples: string[] };
```

- `GET /api/v1/projections` · `GET /api/v1/projections/{id}` → metadados + clusters + gaps. `GET /api/v1/projections/{id}/points?cursor&limit=20000` → `{items: {ref, kind, collection, x, y, z?, cluster, score?}[], next_cursor}` (binário opcional: `Accept: application/vnd.matrix.points+bin` devolve Float32 little-endian intercalado para grandes volumes).
- Clusters por HDBSCAN no espaço original reduzido (PCA 50 antes do UMAP quando `dim` > 50); `-1` = ruído. `top_terms` por TF-IDF dos textos do cluster; `mean_scores`/`error_rate` ligam o cluster aos scores e erros dos traces de origem (consulta ao ClickHouse/Postgres).
- **Lacunas de conhecimento**: cluster cuja maioria é `query` e cuja distância ao `document` mais próximo (cosseno, centroide e vizinho mais próximo) está acima de um limiar (`gap_threshold`, padrão = percentil 90 das distâncias query→documento dos clusters mistos). Ordenadas por `query_count`.
- Determinístico para a mesma semente. Projeção ≤ 50 000 pontos (`sample` estratificado); aviso na resposta quando amostrou.
- `POST /api/v1/projections/{id}/select` `{ids|polygon|cluster}` → `{trace_ids: [], refs: []}`; permite "ver traces" e "adicionar ao dataset" a partir de uma seleção.

## 3. Drift e qualidade de dados

```ts
type DriftConfig = { name: string; reference: Source; current: Source; columns?: string[]; text_columns?: string[]; embedding_collection?: string;
  tests?: Record<string, "auto"|"ks"|"psi"|"wasserstein"|"kl"|"js"|"chi2">; alpha?: number /*0.05*/; psi_threshold?: number /*0.2*/ };
type Source = { type: "dataset_version"|"golden_dataset"|"traces"|"runs_table"|"csv_artifact"; ref: string; window?: {from?: string; to?: string}; sample?: number };
type DriftReport = { id: string; status: ...; created_at: string; summary: {columns: number; drifted: number; share: number};
  columns: {name: string; kind: "numeric"|"categorical"|"text"|"embedding"; test: string; statistic: number; p_value: number|null; drifted: boolean;
            reference: Summary; current: Summary; histogram?: {edges: number[]; reference: number[]; current: number[]}}[];
  quality: {nulls: Record<string, {reference: number; current: number}>; schema: {missing: string[]; extra: string[]; type_changes: {column: string; from: string; to: string}[]};
            correlations: {method: string; matrix: number[][]; columns: string[]}|null; outliers: Record<string, number>};
  text: {descriptors: Record<string, {reference: Summary; current: Summary; drifted: boolean}>} | null;
  embedding: {centroid_distance: number; js_divergence: number; domain_classifier_auc: number; drifted: boolean} | null };
```

- **Testes** escolhidos por `auto`: numérico com ≥ 1000 linhas → Wasserstein normalizado (limite 0,1 do desvio de referência); numérico menor → KS (p < α); categórico com ≤ 2 categorias → proporções (z) / > 2 → χ² (p < α) — para volume grande troca para PSI; texto/embedding conforme abaixo. Cada estatística está disponível explicitamente: KS, **PSI** (10 faixas por quantis da referência, ε para zeros), **Wasserstein**, **KL** e **JS** (sobre histogramas com suavização), **χ²**. Valores devem bater com `scipy.stats`/fórmulas de referência nos testes.
- **Descritores de texto**: comprimento em caracteres e tokens, contagem de palavras, razão de OOV (vocabulário da referência), legibilidade (Flesch adaptado, fórmula documentada), presença de regex proibida (lista do projeto), sentimento léxico simples (lista pequena multilíngue pt/en; marcado como aproximado) e proporção de maiúsculas/dígitos.
- **Embeddings**: distância entre centroides (cosseno), JS entre histogramas da projeção 1-D no eixo do primeiro componente principal conjunto, e **AUC de um classificador de domínio** (regressão logística, validação cruzada 5-fold; AUC ≈ 0,5 sem drift, → 1 com drift); `drifted` se AUC > 0,7 ou centroide acima de limiar calibrado por bootstrap da própria referência.
- **Qualidade**: proporção de nulos, violações de schema (colunas ausentes/extras, mudança de tipo), correlação (Pearson, Spearman; Cramér's V para categóricas), outliers por IQR e z-score robusto (MAD).
- `POST /api/v1/drift/reports` `DriftConfig` → `202`; `GET /api/v1/drift/reports[/{id}]`; relatório guardado como JSON (≤ 5 MB) e histogramas de até 50 faixas.
- **Monitores** `POST /api/v1/drift/monitors` `{config, schedule: {every_minutes: 15..10080}, alert: {share_threshold?: number; columns?: string[]}, enabled}` (admin) · `GET` · `DELETE`; um job `drift.tick` (auto-reagendado, um por monitor) roda o relatório, guarda o último e, quando passa do limiar, cria `Alert` (modelo do ciclo 1, `kind="drift"`, mensagem com as colunas) e aciona as regras existentes por `score`-like `drift_share`.
- Fontes lidas pelo worker com os mesmos filtros de projeto; CSV só de artefato do próprio projeto (G0), ≤ 500 MB.

## Web

`/vectors` — lista de projeções e botão "nova projeção" (coleções, método, parâmetros). `/vectors/[id]`: **projetor 3D em WebGL (deck.gl, `PointCloudLayer`/`ScatterplotLayer` em modo 3D com `OrbitView`)**, 2D alternativo; cor por cluster, origem (`kind`), score ou erro; legenda e filtro por cluster; lasso/retângulo e clique → painel lateral com os textos e links para os traces; "adicionar seleção a um dataset"; painel de clusters (tamanho, termos, scores) e **lista de lacunas** com exemplos. Fallback sem WebGL: SVG 2D. Carrega pontos em páginas binárias e mantém ≤ 100 000 desenhados.
`/drift` — monitores (estado, último share, sparkline), "novo relatório/monitor"; `/drift/[id]` — resumo, tabela por coluna (teste, estatística, p, drift) com histograma sobreposto referência × atual, qualidade (nulos, schema, correlações, outliers), descritores de texto, resultado de embeddings.
