# Contrato G1 — tracking de treino, hardware e avaliação de ML clássico

Decisões: ADR-008. Autorização e papéis: contrato G0 (`require(...)`). Leitura = viewer/`read`; escrita = member/`write`; apagar run = admin.

## Modelo

```ts
type RunStatus = "running"|"finished"|"failed"|"killed";
type Run = { id: string; name: string; status: RunStatus; group: string|null; tags: string[];
  params: Record<string, unknown>;                      // imutáveis depois de definidos
  git: { commit: string|null; branch: string|null; dirty: boolean|null; remote: string|null }|null;
  env: { python: string|null; platform: string|null; hostname: string|null; packages: string[] }|null;  // packages "nome==versão", máx. 500
  summary: Record<string, number|null>;                 // último valor de cada métrica (sem sys/), máx. 200 chaves
  dataset_version_id: string|null;                      // G3
  sweep_id: string|null; parent_run_id: string|null;    // G2
  created_by: string|null; started_at: string; ended_at: string|null; heartbeat_at: string|null; error: string|null };
```

Postgres: `runs`, `run_artifacts(run_id, artifact_id, name, kind: file|model|plot|table|report)`, `run_reports(run_id, kind, name, data JSON, created_at)`. ClickHouse: `run_metrics` (ADR-008). Chave de métrica: `^[A-Za-z0-9_./:@ -]{1,200}$`; prefixo `sys/` reservado à telemetria.

## API (`/api/v1`)

- `POST /runs` `{name?, group?, tags?, params?, git?, env?, dataset_version_id?, sweep_id?, parent_run_id?}` → `201 Run`. Sem `name`, gera `adjetivo-substantivo-N`.
- `GET /runs?status&group&tag&name&sweep_id&q&sort=-started_at&limit&cursor` → `{items: Run[], next_cursor}`; `q` filtra por nome/grupo/tag. `GET /runs/{id}` → `Run` com `summary` calculado.
- `PATCH /runs/{id}` `{name?, tags?, status?, error?}` (status só para `finished|failed|killed`; define `ended_at`) · `POST /runs/{id}/params` `{params}` (mescla; valor igual → ok; valor diferente → `409 {conflicts: [keys]}`) · `POST /runs/{id}/heartbeat` → `204`.
- `POST /runs/{id}/metrics` `{points: [{key, step, value, ts?}]}` (≤ 10 000 pontos e ≤ 2 MiB por requisição; `value` é número ou `"nan"|"inf"|"-inf"`; `step` inteiro ≥ 0; `ts` ISO opcional, padrão agora) → `202 {accepted, rejected: [{index, reason}]}`; run `finished|failed|killed` aceita pontos por 10 min depois do fim e depois `409`.
- `GET /runs/{id}/metric-keys` → `{keys: [{key, count, first_step, last_step, last_value, min, max}]}`.
- `GET /runs/{id}/metrics?keys=a,b&max_points=1000&x=step|time&from_step&to_step` → `{series: {key: {steps: number[], values: (number|null)[], ts: string[]}}, downsampled: boolean}` (M4: até `max_points` pontos por série).
- `GET /runs/compare?run_ids=a,b,c&keys=loss,acc&max_points=1000` → `{runs: {run_id: {name, series: {key: {...}}}}}` (≤ 20 runs, ≤ 20 chaves).
- `POST /runs/{id}/artifacts` `{artifact_id, name, kind}` (liga um artefato do G0; precisa pertencer ao projeto) · `GET /runs/{id}/artifacts` → `{items: {artifact: Artifact, name, kind}[]}`.
- `POST /runs/{id}/reports` `{kind, name, data}` (≤ 2 MiB; tabelas grandes vão como artefato) · `GET /runs/{id}/reports?kind` → `{items: Report[]}`; `DELETE /runs/{id}/reports/{report_id}`.
- `DELETE /runs/{id}` (admin) → `204`; remove linhas relacionais e agenda remoção dos pontos.
- Job `runs.reaper` (a cada minuto, enfileirado pelo próprio worker com chave de dedup): runs `running` sem `heartbeat_at` por > 5 min → `failed` com `error="lost heartbeat"`.

### Relatórios tipados (`data`)

```ts
type ClassificationReport = { labels: string[]; metrics: Record<string, number>;       // accuracy, precision/recall/f1 macro e weighted, log_loss?
  per_class: {label: string; precision: number; recall: number; f1: number; support: number}[];
  confusion_matrix: number[][];                                                       // linhas = verdadeiro, colunas = previsto
  roc: {label: string; fpr: number[]; tpr: number[]; auc: number}[];                  // ≤ 200 pontos por curva; one-vs-rest
  pr: {label: string; precision: number[]; recall: number[]; ap: number}[] };
type RegressionReport = { metrics: {rmse: number; mae: number; r2: number; mape?: number};
  residual_hist: {edges: number[]; counts: number[]};
  sample: {y_true: number[]; y_pred: number[]} };                                      // ≤ 1000 pontos amostrados
type ImportanceReport = { method: "shap"|"permutation"|"model"; features: {name: string; importance: number; std?: number}[] };  // ≤ 100, ordenado
type TableReport = { columns: string[]; rows: unknown[][]; truncated: boolean };       // ≤ 1000 linhas; texto longo truncado em 2000 chars
```
`kind` ∈ `classification|regression|importance|table|custom` (`custom` = JSON livre). Valida estrutura dos tipados (422).

## SDK (`matrix_sdk`)

```python
run = matrix_sdk.start_run(name=None, group=None, tags=(), config=None, system_metrics=True,
                           system_interval=10.0, capture_git=True, capture_env=True, dataset_version=None)
run.log_params({...}); run.log({"loss": 0.2, "acc": 0.9}, step=None)   # step automático (contador por run) quando None
run.log_metric(key, value, step=None); run.log_artifact(path, name=None, kind="file")
run.log_table(name, columns, rows); run.log_report(kind, name, data); run.finish(status="finished")
with matrix_sdk.start_run(...) as run: ...          # exceção → failed com error; KeyboardInterrupt → killed
```
- Envio em segundo plano: fila limitada (100 000 pontos; ao estourar descarta os mais antigos e conta em `run.dropped_points`), lotes de até 1000 pontos ou 1 s, retry com backoff exponencial e jitter, `finish()` descarrega com timeout (padrão 30 s). Nunca bloqueia nem levanta no laço de treino por erro de rede.
- Heartbeat a cada 30 s. `capture_git` roda `git` com timeout curto e ignora falhas; `capture_env` lista pacotes por `importlib.metadata` (máx. 500). Nada de variáveis de ambiente é enviado.
- **Telemetria** (`matrix_sdk.system`): psutil (CPU %, memória usada, I/O de disco e rede, RSS do processo) e NVML via `pynvml` quando existir (por GPU: utilização, memória usada em MB, temperatura, potência em W). Chaves: `sys/cpu.percent`, `sys/memory.used_mb`, `sys/disk.read_mb`, `sys/disk.write_mb`, `sys/net.sent_mb`, `sys/net.recv_mb`, `sys/proc.rss_mb`, `sys/gpu.<i>.utilization`, `sys/gpu.<i>.memory_used_mb`, `sys/gpu.<i>.temperature_c`, `sys/gpu.<i>.power_w`. Funciona sem GPU e sem NVML. O coletor aceita um backend injetável (testes com NVML simulado).
- **Integrações** (extras opcionais `matrix-sdk[hf]`, `[torch]`, `[sklearn]`, `[xgboost]`, `[shap]`):
  - `matrix_sdk.integrations.transformers.MatrixCallback(run=None)` — `TrainerCallback`: repassa todo log numérico do Trainer/TRL (`loss`, `learning_rate`, `grad_norm`, `epoch`, `eval_*`, `rewards/chosen`, `rewards/rejected`, `rewards/margins`, `rewards/accuracies` do DPO/GRPO…) e acrescenta `perplexity = exp(loss)` e `eval_perplexity`; params = `TrainingArguments`; artefato final opcional.
  - `matrix_sdk.integrations.pytorch.watch(model, run, log_freq=100)` — norma global do gradiente, norma dos parâmetros e top-k camadas por norma de gradiente; `log_epoch(run, epoch, **metrics)`.
  - `matrix_sdk.integrations.sklearn.autolog(run=None)` — envolve `BaseEstimator.fit`: params do estimador, tempo de ajuste, score de treino quando houver; desfaz com `autolog(disable=True)`.
  - `matrix_sdk.integrations.xgboost.MatrixCallback` e `...lightgbm.callback(run)` — métricas de avaliação por iteração.
- **Avaliação de ML clássico** (`matrix_sdk.evaluation`, requer scikit-learn): `log_classification_report(run, y_true, y_score=None, y_pred=None, labels=None, name="eval")`, `log_regression_report(run, y_true, y_pred, name="eval")`, `log_feature_importance(run, model, X, y=None, feature_names=None, method="auto")` (`auto`: SHAP médio absoluto se o pacote existir e o modelo for de árvores; senão importância do modelo; `permutation` explícito usa `sklearn.inspection`). Os cálculos acontecem no cliente; o servidor só valida e guarda.

## Web

Rotas: `/runs` (tabela com status, nome, grupo, tags, início, duração, parâmetros-chave e últimas métricas; filtros em URL; seleção de N runs → comparar), `/runs/[id]` (abas: Visão geral — params, git, ambiente, resumo; Gráficos — chaves agrupadas por prefixo, suavização EMA, escala log, eixo passo/tempo, zoom; Sistema — painéis de CPU/RAM/disco/rede/GPU; Artefatos; Relatórios — ROC, PR, matriz de confusão, regressão, importâncias, tabelas), `/runs/compare?ids=` (curvas sobrepostas e diff de parâmetros). Gráficos com Apache ECharts (canvas); nenhum gráfico recebe mais de 5000 pontos por série. Estados vazio/erro/carregando em todas; atualização automática enquanto `running`.
