# Contrato G6/G7 — runner isolado, agentes em sandbox (Inspect AI) e benchmarks (lm-eval / VLMEvalKit)

Decisões: ADR-010. O runner é um serviço separado (`matrix-runner`) sem acesso ao banco: fala com a API do MATRIX com uma **chave de runner**. Papéis: ver = viewer; criar tarefa/execução = member (admin para tarefas com sandbox com rede ou imagem não padrão); registrar runner/chaves de runner = admin.

## Runner

- `POST /api/v1/runners` `{name, capabilities: ["inspect","lmeval","vlmeval"], labels?}` (admin) → `201 {runner, key: "mxr_…"}` (segredo uma vez; escopo único `runner`; só funciona em `/api/v1/runner/*`).
- Protocolo do runner (HTTPS, chave `mxr_`): `POST /api/v1/runner/claim` `{capabilities}` → `200 {job}` ou `204` (long-poll ≤ 25 s) · `POST /api/v1/runner/jobs/{id}/heartbeat` · `POST .../events` (log de progresso) · `POST .../traces` (OTLP/JSON por amostra, mesmas regras de normalização do ciclo 1) · `POST .../results` (resultado normalizado) · `POST .../complete|fail`. Lease com expiração e reentrega; resultados idempotentes por `(job, sample, kind)`.
- Execução local do runner: `matrix-runner --api … --key-env MATRIX_RUNNER_KEY` laço claim→executar→reportar; concorrência configurável; encerramento limpo.

## G6 — avaliação de agentes (Inspect AI)

```ts
type AgentTask = { id: string; name: string; description: string|null; spec: AgentTaskSpec; created_at: string };
type AgentTaskSpec = {
  samples: { id: string; input: string; target?: string|string[]; files?: Record<string, string /*conteúdo texto ou "artifact:<id>"*/>; setup?: string; metadata?: Record<string, unknown> }[];
  solver: { type: "react"|"basic"|"plan_and_solve"|"multi_agent"; tools: ("bash"|"python"|"read_file"|"write_file"|"web_search")[]; max_messages?: number; system_prompt?: string };
  scorer: { type: "exact"|"includes"|"file_exists"|"command"|"model_graded"; path?: string; command?: string; expect_exit?: number; rubric?: string };
  sandbox: { image: string /* da allowlist do operador */; network: "none"|"allowlist"; cpu: number; memory_mb: number; timeout_s: number; pids: number };
  model: { provider: string; name: string; base_url_env?: string|null; api_key_env?: string|null };
};
type AgentRun = { id: string; task_id: string; status: "queued"|"running"|"done"|"failed"|"cancelled"; model: {...};
  summary: { samples: number; accuracy: number|null; mean_score: number|null; errors: number; total_tokens: number; cost_usd: number; duration_s: number };
  created_at: string; finished_at: string|null; runner_id: string|null };
```
- `POST/GET /api/v1/agent-tasks` · `GET /agent-tasks/{id}` · `POST /agent-runs` `{task_id, model?, limit?, epochs?, seed?}` → `202` · `GET /agent-runs[/{id}]` · `GET /agent-runs/{id}/samples` → `{items: {sample_id, status, score, answer, trace_id, error, duration_s, tokens}[]}` · `POST /agent-runs/{id}/cancel`.
- Cada amostra vira um **trace** do MATRIX (`trace_id` na resposta) reutilizando o inspector; spans AGENT (raiz da amostra), LLM (cada geração), TOOL (cada chamada: comando, saída truncada, código de saída), com `agent_run_id` em `session.id`.
- Scorers `file_exists` e `command` executam **dentro** do sandbox da amostra (teste unitário/arquivo criado). `model_graded` usa o juiz do ciclo 1.
- **Sandbox por amostra** (ADR-010): `--network none`, `--user 65534`, `--read-only` + tmpfs, `--cap-drop ALL`, `no-new-privileges`, limites de CPU/memória/PIDs/tempo, volume efêmero apagado ao fim, imagem **só da allowlist** (`MATRIX_RUNNER_IMAGE_ALLOWLIST`). Tarefas com `network: "allowlist"` precisam de admin. Saída das ferramentas é truncada (64 KB) e tratada como dado não confiável.
- Integração real: o runner monta uma `inspect_ai.Task` a partir do spec (Dataset → Solver → Scorer), executa com `inspect_ai.eval`, lê o `EvalLog` e traduz eventos em spans.

## G7 — benchmarks fundacionais

```ts
type BenchmarkSpec = { engine: "lm_eval"|"vlmeval"; tasks: string[]; num_fewshot?: number; limit?: number; batch_size?: number|"auto";
  model: { backend: "openai_chat"|"openai_completions"|"hf"; base_url_env?: string|null; api_key_env?: string|null; name: string; model_version_id?: string|null; device?: "cpu"|"cuda"; dtype?: string; peft?: string|null };
  seed?: number };
type BenchmarkResult = { run_id: string; model: string; model_version_id: string|null; task: string; metric: string; value: number; stderr: number|null;
  n_samples: number|null; num_fewshot: number|null; task_version: string|null; engine: string; engine_version: string };
```
- `POST /api/v1/benchmarks` `BenchmarkSpec` → `202` · `GET /benchmarks[/{id}]` · `GET /benchmarks/{id}/results` · `POST /benchmarks/{id}/cancel`.
- **Leaderboard**: `GET /api/v1/leaderboard?tasks=a,b&metric=acc&model_prefix=` → matriz modelo/versão × tarefa com melhor resultado e `n`; `GET /leaderboard/compare?a=<model_version>&b=<model_version>` → deltas por tarefa com intervalo (usa `stderr` quando existir) — base × fine-tune. Ligação com registry e linhagem: `evaluated_by` (G3).
- Tarefas permitidas: lista do operador (`MATRIX_BENCHMARK_TASKS`, padrão: tarefas leves como `arc_easy`, `hellaswag`, `gsm8k`, `mmlu` subconjunto, `ifeval`; VLM: `MMBench`, `POPE`); `limit` obrigatório acima de N amostras sem aprovação de admin.
- Versões do engine e da tarefa gravadas para reprodutibilidade; resultados com `engine_version` diferente não entram na mesma coluna do leaderboard sem aviso.

## Web

`/agents` (tarefas e execuções; criar tarefa com editor de spec e validação), `/agents/runs/[id]` (resumo, amostras com score, **transcrição** — abre o trace no inspector —, saída do sandbox), `/benchmarks` (lançar, progresso), `/leaderboard` (matriz com ordenação e filtros, comparação base × fine-tune com barras de delta), `/runners` (admin: runners, chaves, estado).
