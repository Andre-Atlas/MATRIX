# Contrato G8 — AI Gateway

Decisões: ADR-011. Dois planos: **controle** (API do MATRIX, `/api/v1/gateway/*`, papéis do G0) e **dados** (processo `matrix-gateway`, `/gateway/v1/*`, chave virtual). Admin gerencia rotas e chaves; viewer lê consumo.

## Plano de dados (compatível com OpenAI)

- `POST /gateway/v1/chat/completions` (com `stream: true` via SSE), `POST /gateway/v1/embeddings`, `GET /gateway/v1/models`. Autenticação `Authorization: Bearer mxg_…`. O campo `model` é um **alias** resolvido para uma rota; aceita também `provider/modelo` quando a chave permite.
- Erros no formato OpenAI (`{"error": {"message", "type", "code"}}`): `401`, `403` (modelo não permitido), `429` (limite, com `Retry-After` e `x-ratelimit-*`), `402`-like `429 budget_exceeded`, `502`/`504` do provedor após fallbacks.
- Cabeçalhos de resposta: `x-matrix-route`, `x-matrix-provider`, `x-matrix-cache: hit|miss|semantic`, `x-matrix-cost-usd`, `x-matrix-trace-id`. Cabeçalhos de entrada opcionais: `x-matrix-session-id`, `x-matrix-user-id`, `x-matrix-tags`, `x-matrix-no-cache`.
- Providers suportados: `openai` (e compatíveis: vLLM, SGLang, Ollama, Azure via base URL), `anthropic` (tradução OpenAI ⇄ Messages, inclusive tool use e streaming), `fake` (determinístico, para testes). Parâmetros não suportados pelo provider são descartados e avisados em `x-matrix-warnings`.

## Plano de controle (`/api/v1/gateway`)

```ts
type Route = { id: string; alias: string; strategy: "single"|"fallback"|"weighted"|"ab";
  targets: { provider: "openai"|"anthropic"|"fake"; model: string; base_url_env?: string|null; api_key_env?: string|null; weight?: number; timeout_s?: number; max_retries?: number }[];
  fallback_on: ("timeout"|"5xx"|"429"|"error")[]; cache: { exact: boolean; semantic: boolean; ttl_s: number; threshold?: number };
  store_content: "full"|"hash_only"|"none"; enabled: boolean };
type VirtualKey = { id: string; name: string; prefix: string; allowed_aliases: string[]; rpm: number|null; tpm: number|null;
  budget_usd_day: number|null; budget_usd_month: number|null; expires_at: string|null; revoked_at: string|null; created_at: string; spent_usd_day: number; spent_usd_month: number };
```
- `POST/GET/PATCH/DELETE /routes` (admin; valida que as variáveis de ambiente referenciadas **existem** no servidor sem devolver valor; `weight` soma > 0; `ab` aceita `experiment: {name}`).
- `POST /virtual-keys` `{name, allowed_aliases, rpm?, tpm?, budget_usd_day?, budget_usd_month?, expires_at?}` → `201 {key: VirtualKey, secret: "mxg_…"}` (segredo só nesta resposta) · `GET` · `PATCH` · `DELETE` (revoga) — admin.
- `GET /usage?from&to&group_by=alias|key|model|day` → `{items: {group, requests, input_tokens, output_tokens, cost_usd, errors, cache_hits, p50_ms, p95_ms, ttft_p50_ms}[]}` (viewer) · `GET /ab/{name}` → resultado comparativo por braço (volume, latência, custo, scores se houver).

## Comportamento

1. **Resolução**: alias → rota → alvo conforme estratégia (`fallback` em ordem; `weighted`/`ab` por peso com sorteio **determinístico por `x-matrix-session-id` ou hash do usuário**, para a mesma sessão ficar no mesmo braço).
2. **Retries e fallback**: por alvo até `max_retries` com backoff e jitter nas condições de `fallback_on`; depois passa ao alvo seguinte; streaming só faz fallback antes do primeiro byte enviado ao cliente.
3. **Rate limit**: janela deslizante por chave para requisições/min e tokens/min (contagem de tokens de entrada estimada antes e corrigida com o uso real depois). **Orçamento** diário/mensal por chave: bloqueia ao atingir; custo pelo motor de preços do ciclo 1.
4. **Cache exato**: chave = hash(projeto, alias, mensagens normalizadas, parâmetros relevantes); só para `temperature <= 0.2` por padrão e sem `tools` dependentes de estado. **Cache semântico**: embedding da última mensagem do usuário (provider de embeddings configurável; `hash` offline em testes), busca por similaridade de cosseno ≥ `threshold` dentro do mesmo alias e histórico equivalente; hits devolvem `x-matrix-cache: semantic`. Streaming de resposta em cache é reproduzido em chunks. `x-matrix-no-cache` ignora.
5. **Trace automático**: cada chamada vira um trace no MATRIX (`LLM` span com modelo, provider, mensagens conforme `store_content`, tokens, custo, **TTFT**, cache, rota, tentativas e fallback como eventos), pela mesma normalização OTLP/OpenInference do ciclo 1 (chamada interna ao store, sem passar pela rede). O `session.id`/`user.id` vêm dos cabeçalhos.
6. **Segurança**: resposta de erro nunca ecoa chave/URL do provedor; `api_key_env` resolvido por chamada; logs sem corpo; limite de tamanho de corpo e de `max_tokens` por chave; `n` > 1 e `logit_bias` abusivos limitados; headers hop-by-hop removidos.

## SDK e web

SDK: `matrix_sdk.gateway.client(virtual_key)` retorna `openai.OpenAI(base_url=…, api_key=virtual_key)` quando `openai` existe (extra), senão um cliente httpx mínimo. Web: `/gateway` (rotas com editor e teste "enviar uma mensagem", chaves virtuais com consumo e orçamento, uso por alias/modelo/dia, experimentos A/B, taxa de cache, latência e TTFT).
