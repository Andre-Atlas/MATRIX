## Sandboxes — achados críticos do main que TODOS devem ser fechados
1. **Remova a execução no host.** `LocalSandbox` (roda `bash -c`/`python -c` no servidor com o `os.environ` inteiro: JWT/chaves/URLs de banco) e o fallback silencioso `DockerSandbox → LocalSandbox` deixam de existir. Backends: `docker` (padrão) e `fake` (**só** em `MATRIX_ENV=test`/dev explícito; nunca executa código do usuário; saída determinística; resultados `simulated=true`). Docker indisponível ⇒ **falha fechada** (`sandbox_unavailable`), sem executar nada no host. Teste: aponte `DOCKER_HOST` para um socket morto e monkeypatche `subprocess`/`os.system` para provar que nada roda no host.
2. **`docker run` endurecido**, construído em UM lugar (`build_docker_run_args`): `--rm --name matrix-sbx-<run>-<sample>-<rand> --init --network none --read-only --user 65534:65534 --cap-drop ALL --security-opt no-new-privileges:true --pids-limit <cfg, 128> --memory <cfg, 512m> --memory-swap <igual> --cpus <cfg, 1, máx 4> --tmpfs /tmp:rw,noexec,nosuid,size=256m --ipc none` (+ ulimits razoáveis). **Imagem só da allowlist do operador** (`MATRIX_SANDBOX_IMAGES`, padrão `python:3.12-slim`; fora da lista ⇒ 422). **Nenhum `-v` do usuário**: o runner cria um diretório temporário 0700 por amostra montado só em `/workspace` (apagado ao fim); `mounts`/`volumes` na política ⇒ 422. **Rede: só `none`**; qualquer outro valor ⇒ 422 ("network access for sandboxes is not supported until an egress proxy exists"); remova o fluxo "admin aprova rede" (ou deixe só como erro explicativo). O CLI `docker` roda com ambiente **mínimo** (PATH, DOCKER_HOST, HOME vazio): nenhuma variável do servidor vaza para o CLI nem para o container (teste com `MATRIX_SECRET_PROBE=x`).
3. **Timeout e limpeza:** no timeout `docker kill <name>` + `docker rm -f <name>` (o `subprocess.run` só mata o cliente); sempre remova container e tmpdir no `finally`; stdout/stderr truncados em 64 KiB; exit 137 por memória ⇒ `oom`. Depois de timeout e de OOM `docker ps -a --filter name=matrix-sbx` não lista nada.
4. `sync_exec` só em `MATRIX_ENV=test`; em produção sempre via worker. `is_admin`/`network_approved_by` vindos do cliente já são recusados (T3): confirme.
5. Artefatos do sandbox entram por `store_bytes` do branch (já na T4): confirme quota e projeto.
6. Campo `simulated` (bool) nas execuções/resultados (coluna via fragmento) e no schema; `fake` ⇒ true, `docker` ⇒ false. Documente a interface `SandboxEngine` (docker, fake); Inspect AI real é o destino (ADR-010), **não** implementar agora.
Testes (marcador `docker`; pulam só se `docker info` falhar, com o motivo exato **"Docker daemon not available"**, que deve entrar na allowlist de `scripts/check_skips.py` + teste em `tests/test_check_skips.py`): sem rede (interfaces = só `lo`), escrita em `/etc` bloqueada, uid 65534, OOM → 137 → `oom`, timeout mata e remove o container, env do servidor não vaza, mount do usuário recusado, imagem fora da allowlist recusada, daemon morto ⇒ falha fechada, fork bomb contida pelo pids-limit, 20 execuções paralelas sem container órfão. Prove com uma mutação rápida que os testes de contenção **falhariam** sem a correção.

## Benchmarks
7. `runner_config.api_key` está em claro no banco e a API o devolve: **nunca mais.** O cliente passa só `api_key_env` (NOME de variável de ambiente do servidor, `^[A-Z][A-Z0-9_]{0,63}$`); `api_key` literal ⇒ 422 mandando usar `api_key_env`; respostas e logs sem segredo (teste com valor sentinela em `caplog` e na resposta); fragmento de migração que **zera** `api_key` das linhas existentes.
8. **SSRF:** runner `http`/`vllm` passa a usar o `egress_client` do branch (allowlist por projeto, IP fixado, redirect revalidado, auditoria). Remova `validate_runner_url` próprio (DNS resolvido duas vezes ⇒ rebinding; `gaierror` ignorado). Host fora da allowlist ⇒ job falha com erro claro. Testes com os seams `egress.set_resolver_for_tests`/`set_dialer_for_tests` e um servidor HTTP local falso compatível com OpenAI.
9. **`local_sim` não pode parecer resultado real:** continua como motor padrão de demonstração mas todo `benchmark_task_results`/`benchmark_runs` carrega `simulated=true` (coluna via fragmento; API e schema). Defina a interface `BenchmarkEngine` (`local_sim`, `http`, stubs `lm_eval`/`vlmeval` que levantam `EngineUnavailable("install the real engine")` quando a biblioteca não está instalada). **Não** implemente lm-eval/VLMEvalKit agora. Resultados de `http`/`vllm` reais ⇒ `simulated=false`.
10. O httpx do runner de benchmarks usa as configurações de proxy de `matrix_server/net.py` (T3) quando não for egress.
